# 문제 목록 API 성능 측정 결과

perf/summarize.py 가 원본 파일(`*-run*.json`, `*-server.json`)에서 만든 표다. 측정 조건은 `env.txt`.

| 단계 | 처리량 (req/s, 중앙값) | p95 (ms) | p99 (ms) | 요청당 SQL | 측정 후 Redis 키 | ① 대비 처리량 |
|---|---|---|---|---|---|---|
| ① 개선 전 (AlgorithmTag @BatchSize 없음, 캐시 없음) | 1,676 (1,675, 1,677) | 55.02 (55.09, 54.95) | 66.11 | 21.00 | 0 | 1.00× |
| ② @BatchSize | 3,603 (3,544, 3,662) | 27.34 (28.11, 26.56) | 39.08 | 4.00 | 0 | 2.15× |
| ③ @BatchSize + Redis 캐시 | 12,950 (13,057, 12,843) | 7.97 (7.92, 8.02) | 12.61 | 0.00 | 1 | 7.73× |

- 실패율: 모든 실행에서 최대 0.00%
- 처리량·p95 괄호 안은 본 측정 각 회의 값, 바깥은 중앙값
- 요청당 SQL = 측정 동안 앱이 실행한 SQL 수(Hibernate 통계, 워밍업 포함) ÷ /api/problems 요청 수
- 측정 후 Redis 키: 1·2 단계는 0 이어야 캐시가 꺼진 것, 3 단계는 1(같은 요청이라 키 하나)

→ @BatchSize 로 2.15배, 캐시를 더해 누적 7.73배. p95 55.0 ms → 8.0 ms.
